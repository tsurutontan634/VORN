# まちねこ事務局AI（仮称）— VORN Challenge 2026 プロトタイプ

地域猫活動（京都市では「まちねこ活動」）の **申請・計画書・周知・日程・年次報告・3年更新という事務** を、無償ボランティアの代わりに LLM が引き受けるツール。
1つのコロニー（猫の群れ）を「町内会の同意が取れた後」から「完了報告」まで、事務ゼロで通す。

背景・一次情報・戦略は `HANDOFF.md`、作業ルールは `CLAUDE.md`。

## 誰が、何に使うか

- **使う人**：京都市内で地域猫の世話をしている個人ボランティア。町内会等への説明と同意は済んでいる前提。
- **やること**：会話で猫の状況を聞き取り → 京都市の要綱に照らして不足を指摘 → 第1号様式・第6号様式を埋めた DOCX を出力 → 周知チラシ → 登録から3年更新までの日程表 → 期限のリマインド一覧。
- **やらないこと**：捕獲の手順、町内会への説得、里親探し、子猫の育て方。聞かれたら範囲外と断る。

## なぜ AI か（設計の核）

自治体ごとに要綱が違い、それが自然言語（PDF/DOCX）で公開されている。
このツールは **要綱をコードに書かない**。`municipality/<自治体>/sources/` に置いた一次資料を LLM がそのまま読み、規則・様式の項目・工程・期限を毎回抽出する。
自治体を替えるときはフォルダを差し替えるだけ（実装は京都市のみ）。

## 画面の流れ（左メニューの 1→6）

| 工程 | 何をするか | LLM の役割 | コードの役割 |
|---|---|---|---|
| 1. 聞き取り | チャットでコロニー情報を集める | 質問を出し、回答を構造化データに変換 | データの保持・表示 |
| 2. 要綱照合 | 規則を抽出し、不足・注意・OK を出す | 一次資料から規則抽出（根拠の引用付き）→ 照合 | 表示 |
| 3. 書類出力 | 第1号様式・第6号様式を埋める | 様式の項目名と記載例を読み、値を作る | DOCX 生成（配布様式があれば転記） |
| 4. 周知チラシ | 「地域へのお知らせ」本文 | 参考様式に沿って本文生成 | 表示・ダウンロード |
| 5. 日程表 | 申請→審査→登録→周知→捕獲→持込→リターン→年次報告→更新 | 工程・誰が日程を決めるか・期限の根拠を抽出 | **日付計算**（LLM に計算させない） |
| 6. リマインド | 年次報告・更新・廃止届 | — | 日程表から生成 |

スクリーンショットは `docs/screenshots/`。

## 動かし方

```bash
pip install -r requirements.txt
export ANTHROPIC_API_KEY=sk-ant-...   # 無ければモック応答で動く
streamlit run app.py
```

- APIキーが無いときは **モック応答** に自動で切り替わる（サイドバーに表示）。モックは UI を最後まで通すための固定台本で、`machineko/mock.py` にある。本番経路では使わない。
- モデルは環境変数 `MACHINEKO_MODEL` で変更可（既定 `claude-sonnet-5`）。
- `MACHINEKO_MOCK=1` でキーがあってもモックを強制。
- テスト：`python -m pytest -q`

## 一次資料の配置（重要）

`municipality/kyoto/sources/` に京都市の配布ファイルを置くと、自動で読み込まれる。
必要なファイルは `municipality/kyoto/profile.yaml` と `sources/README.md` に列挙。
**現状は `notes.md`（市HPからの抜粋メモ）だけ** が入っており、要綱PDF・様式DOCX・記載例PDF は未配置。
様式DOCXが無い間は python-docx で代替の書類を生成し、その旨を書類内に明記する。

## 構成

```
app.py                      Streamlit UI（1画面、左メニューで工程を切替）
machineko/
  profile.py                自治体プロファイルと一次資料の読み込み（PDF/DOCX/MD → テキスト）
  colony.py                 コロニー情報のデータ構造と JSON Schema
  llm.py                    Anthropic API ラッパー（構造化出力・prompt caching・モック切替）
  intake.py                 1. 聞き取り
  rules.py                  2. 要綱照合（規則抽出 → 照合）
  documents.py              3. 書類出力（項目生成 → DOCX）
  flyer.py                  4. 周知チラシ
  schedule.py               5. 日程表 と 6. リマインド（日付計算はここ）
  mock.py                   APIキー無しで動かすための固定応答
municipality/kyoto/
  profile.yaml              自治体の基本情報と資料一覧（規則は書かない）
  sources/                  一次資料の置き場
demo/sample_colony.json     デモ用コロニー（左京区・11頭・活動者3名）
tests/                      日付計算とモック経路の一気通貫テスト
```
